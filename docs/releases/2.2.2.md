## Behavior

- The main button starts a connection, cancels a pending connection, or
  disconnects an established tunnel. Pending connection has a close icon and
  the Russian label «Отменить подключение». The initial settings/profile wait
  is covered too. Repeated cancellation clicks are coalesced during cleanup.
- Manual cancellation immediately invalidates automatic fallback/recovery.
  A stale success/status reply cannot restore the cancelled UI state.
- Windows IPC keeps accepting authenticated local clients while one dedicated
  worker owns all native engine handles and executes commands sequentially.
  A fully decoded Disconnect signals cooperative cancellation at ingress.
- Disconnect reuses the pending Connect operation ID when cancelling. The
  service remembers a bounded set of revoked IDs, including a Connect which
  arrives after its cancellation. These attempts are discarded before changing
  service state. The v4 wire format remains compatible.
- AWG handshake, SCM startup and Xray route waits check cancellation. Engine
  utility commands have bounded waits. Cleanup is deliberately not cancelled;
  the UI confirms disconnection only on the service response. Windows driver
  shutdown can still take several seconds; IPC has a finite timeout.
- Disconnect can recover a stale transitional state. Cleanup/profile-load
  errors no longer strand the state machine in Connecting/Disconnecting.
- Persistent kill switch is not disabled by cancellation or service shutdown.
  Service shutdown waits for its worker and cleans native engines before exit.

and kill-switch traffic behavior still require installation and a separately
approved live test that may interrupt internet access. Unit/IPC tests are not
a substitute for that live check.
