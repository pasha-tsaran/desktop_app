## Application changes

- Only Favorites and All countries filters remain above the server list.
- All countries clears the Favorites filter.
- Compact connection panel fits the supplied 1266x682 client area; the bottom
  Ping tile is removed and the panel has no internal scroll view.
- The top-right Check ping button shows progress and the measured result.
- Release ping uses a bounded TCP connection to the configured API origin,
  currently 88.218.94.3:9443 on the same MVP server. This is TCP connection
  latency, not ICMP or a separate VPN protocol handshake measurement. The OS
  chooses the route; this probe does not alter routing/firewall settings.
- A failed repeat probe clears the prior cached latency. Ping does not claim
  the VPN tunnel is healthy or modify connection permissions.

## Architecture and compatibility

Flutter UI delegates account/profile handling to kenai_core and infrastructure
adapters. The production WindowsVpnEngine sends typed IPC v4 operations to
KenaiVpnService; the service owns AmneziaWG and Xray lifecycle, routes and DNS.
Account/profile storage keys, profile provisioning, protocol opcodes, API URL
and installer upgrade handling are unchanged by this UI update. Upgrade
preserves stored activation/profile data; uninstall removes it.

## Reproduction

Use `tool/build-ui-update.ps1` with the audited baseline installer and a 7-Zip
executable. It verifies the baseline hash, builds Flutter release 2.1.10+10,
copies the entire baseline service/license payload, compiles NSIS, extracts the
result and checks all eight service files again. It never installs the result.
The usual `build-windows-installer.ps1` rebuilds the current service sources
(2.1.9 engine behavior); it is NOT the build recipe for this preserved-engine
artifact. Existing source changes belonging to earlier work were retained.
