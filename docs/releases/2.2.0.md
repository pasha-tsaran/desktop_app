## Implemented behavior

- Automatic protocol selection uses server-supported, engine-supported
  protocols: VLESS Reality, then AmneziaWG, then WireGuard if actually offered.
  A manually selected protocol does not silently fall back to another protocol.
- The default server is restored from saved settings. The current production
  catalog contains only Armenia; this change does not add fictional servers.
- Auto-connect establishes the tunnel when the application starts, provided
  there is an activated account. It can use the selected or recommended server.
- Launch-at-login adds/removes the current user's `KenaiVPN` Run value using
  native registry APIs and a quoted, internally derived executable path. It
  launches the app at Windows sign-in, not a VPN before Windows sign-in.
- Network changes are detected through native adapter/address/gateway state.
  Notifications are debounced; VPN tunnel aliases are excluded. Recovery runs
  only when enabled and a connection is wanted. Manual disconnect cancels it.
- Suspend/resume notifications restore the previously wanted connection only
  when the selected sleep policy permits. A simultaneous network notification
  does not override the sleep policy.
- Minimize-after-connect runs only on transition to connected, not on every
  statistics/status refresh. It minimizes to the taskbar.
- The application must remain running (minimized is fine) for automatic
  network/sleep recovery. The kill switch itself is service-owned.
- DNS override remains disabled: the existing dropdown did not implement an
  override. DNS continues to come from the VPN profile.
- Production copy no longer describes the real adapter as a mock. Mock means
  an isolated test implementation and remains available in debug/test builds.

## Persistent kill switch

The user chose strict behavior: manual VPN disconnect does not restore ordinary
Internet. Protection is released only by disabling the setting or uninstalling
the application. Closing the GUI/service does not remove committed filters.

The privileged service owns persistent Windows Filtering Platform IPv4/IPv6
outbound filters. Replacements are transactional. Only the fixed Kenai filter
keys are changed. Tunnel LUID, loopback, the current VPN peer and the fixed MVP
API host are permitted, as are DHCP broadcast and IPv6 link-local multicast
needed for network recovery. API/peer exceptions are host-wide, not per-port.
Other direct outbound traffic is blocked, including LAN unicast and direct DNS.

This is persistent BFE policy, not a boot-start network driver: no guarantee is
made for the early boot interval before the Windows filtering engine loads its
persistent policy. Hostname VPN endpoints are rejected under protection rather
than opening a temporary external DNS exception; current profiles use IPs.

The typed IPC adds opcode 10 with a strict boolean. It retains caller/session
authorization. Disconnect is idempotent and reports actual backend protection,
including when no tunnel is connected. The GUI does not execute shell commands
or modify firewall/routes/drivers.

Uninstall runs the service's fixed administrator-only `/clear-kill-switch`
cleanup before deleting its executable. If cleanup fails, uninstall aborts.
Before downgrading to 2.1.10 or older, disable kill switch in 2.2.0 first: older
services do not understand the new policy. Do not delete the service manually
while protection is enabled.

## Build and preservation of working engines

`tool/build-system-update.ps1` builds fresh Flutter and Rust executables and
copies engine/driver/license payloads from the audited working 1.1.8 installer.
It verifies the baseline installer's SHA-256, then extracts the resulting
installer and checks payload hashes again. It never installs the result.

Unlike UI-only 2.1.10, the first-party service must change to implement WFP and
the new IPC command. AmneziaWG, awg.exe, Xray, Wintun and WireGuard payloads are
not upgraded. Xray's allow-list explicitly includes the baseline executable.
Byte identity of engines reduces risk but is not a substitute for live tests
of their integration with the new service.
